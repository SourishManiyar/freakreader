# Reference oracle: statements, proofs and mentions known from the DVI

This directory measures the detection of theorem-like statements, proofs and in-text references
(`pdfcraft_render::text::page_layout::refs`, and the graph `pdfcraft_engine::references` builds on
it): synthetic papers whose LaTeX we wrote and compiled ourselves, so which glyphs make up each
Theorem, Lemma, Definition, Remark or Proof, which glyphs make up each mention ("Lemma 2.1",
"(3.4)", "Section 3") and which block each mention names are TeX's own answer. It extends the layout
oracle (`../../layout/oracle/README.md`) and uses its truth as is.

## Files

| File | What it is |
|---|---|
| `papers.toml` | The paper list: class, options, geometry, theorem head style, numbering, shared counter, end-of-proof mark, hyperref, a seed, and the body as directives (`begin lemma label=lem:a 2`, `proof of=thm:a`, `say lem:a+lem:b and`, `say ext thm:a`, …). Written for this repository. Papers whose id starts `ho_` are held out. |
| `pdfcraftlayout.sty` | The layout oracle's bracket package, as compiled. |
| `pdfcraftrefs.sty` | This oracle's bracket package (`pdfcraft_oracle::tex::refs::package`), as compiled. |
| `<paper>.tex`, `<paper>.pdf` | Each paper, generated from `papers.toml`. Statements and prose are made up by a seeded generator from the layout oracle's word lists (`xtask/src/layout_oracle.rs`): our own made-up mathematics, no text from papers or books. |
| `truth.tsv` | The layout truth of the papers (blocks, every glyph and rule), and their statements (printed word, number, name, style, what a proof proves, its end mark), labels (the block each names) and mentions (clickable glyphs and target). Format: `pdfcraft_oracle::tex::refs::RefsTruth`. |

All but `papers.toml` and this README are generated by `cargo xtask refs-oracle generate` and must not
be edited.

## How the truth is made

The layout oracle's brackets stay; this oracle adds `\special{pdfcraft:layout:x:…}`, which the layout
truth passes over:

- **Statements and proofs.** The source writes `\pdfcraftthm{s3}\begin{lemma}…\end{lemma}\pdfcraftthmend`.
  Those macros only set a flag; the specials are put at the start of the next paragraph (or
  display), where the layout package's paragraph hook already puts one, so no whatsit lands
  anywhere new. The begin special carries `\@currentlabel`, the number amsthm just stepped. A
  statement's glyphs are those shipped between its brackets that the layout truth gives to a
  paragraph, display, list item or other text, not a float, footnote or running head shipped
  meanwhile. The printed word, numbered or not, the name, the style and, for a proof, what it
  proves (the statement its head names, else the one before it) and whether it has an end mark are
  the generator's, which wrote the source.
- **Mentions.** `\pdfcraftref{m7}Lemma~\ref{lem:a}\pdfcraftrefend{}` brackets exactly the glyphs that
  should be clickable, here `Lemma 2.1`; `\pdfcraftextra(ii)\pdfcraftextraend{}` marks what may go
  with it either way (`Proposition 2.1(ii)`). The target is the label's block: a statement, the
  heading or caption after `\pdfcraftmark`, or the display bracketed `pdfcraft:eq:ID`. A mention of
  another work (`Theorem~\ref{x} in~[5]`, `of~[Smith]`, `of the appendix of~[3]`, `in the book~[2]`)
  or of a block that is not there (`Lemma~9.7`) has no target: resolving it to nothing is right.
  The brackets wrap the source rather than patch `\ref`, so the kind word is inside them;
  `\eqref` is the bracketed reference set inside its own `\textup` group (a whatsit before it
  would change LaTeX's italic-correction check and move glue). `\autoref` is used only in the
  linked papers.
- **Two guards the layout package did not need.** A paragraph left empty after a display (a
  statement or proof ending in one) is dropped by TeX unless something is in it, and the layout
  package's paragraph-end special would be: this package's hook leaves an empty paragraph alone.
  And `\eqref`'s number is set with amsmath's own `\maketag@@@`, not the layout package's bracketed
  one, so a mention is not taken for an equation's tag.

Each PDF is compiled again with both packages reduced to empty macros and must come out
**byte-identical** (`generate` fails otherwise; it caught both guards above, and the `\textup`
case). Generation runs pdfTeX twice to DVI (labels) and twice to PDF, without shell escape, with
`SOURCE_DATE_EPOCH=1700000000` and `FORCE_SOURCE_DATE=1`; `generate --check` regenerates into a
temporary directory and compares every file. Only AMS Type 1 fonts may be embedded (Computer Modern,
OFL-1.1, `../../math/OFL-AMSFonts.txt`), and no reference may be left undefined.

**Linked papers.** The two papers with `hyperref = true` carry no DVI truth: hyperref's DVI driver
places some glyphs apart from where its PDF driver does, so the DVI does not describe their PDF. They
are checked against their own links instead (every link to a block has an inferred mention under it
that goes to the same place), and with the brackets reduced to nothing they must draw the same
glyphs within 0.2 pt (both came out byte-identical). The hyperref papers of the reference previews
(`../../hyperref`, written apart from this oracle) are checked the same way by
`crates/engine/tests/it/reference_graph.rs`.

## Scoring

- **Statements and proofs** (each a glyph set): a found one is the *detection* of a truth one when
  their glyph sets agree with an F1 of at least 0.5 (matched one to one, best first); its *extent* is
  right at F1 ≥ **0.9**. Per detected statement: the printed word, the number and the name right.
  Spurious: found ones that stand for none.
- **Proofs:** of the detected ones, `proves` the right statement, a wrong one, none; end mark found
  where there is one, and where there is none.
- **Mentions** (clickable glyphs, the optional extra counted on neither side): matched at F1 ≥ 0.8.
  Recall over truth mentions, precision over found ones.
- **Resolution** of matched mentions: the right target (the found target's glyphs match the truth
  target's at F1 ≥ 0.5), none where the truth has none, **a wrong target** (another block, or a
  block where the truth has none), none where the truth has one (missed). *Wrong links* are those
  plus links from found mentions that stand for no truth mention; they matter most and are reported
  first.

Everything is reported for development and held-out papers apart, per statement word, per target
kind, per head style, per class and column layout, and per numbering.

```sh
cargo xtask refs-oracle report                                  # the analysis, dev and holdout apart
cargo xtask refs-oracle report --analyser all                   # with the deliberately broken analysers
cargo xtask refs-oracle report --dev                            # development papers alone (while changing the code)
cargo xtask refs-oracle report --failures                       # the development papers' statements and mentions, one by one
cargo xtask refs-oracle generate --check                        # regenerate (needs TeX Live), require identical bytes
cargo xtask refs-oracle test                                    # the oracle's tests
```

Three broken analysers prove the harness discriminates (`broken_analysers_score_badly`): one that
trusts the number and ignores the word (a mention goes to any statement with its number), one that
links every `(n)` it sees to the display with that number, one that never ends a proof before the
next statement.

## Scores

Measured on 2026-11-17 on branch `feat/theorem-blocks` with pdfTeX 1.40.25 (TeX Live 2023/Debian).
The held-out papers were written before the analysis and read only through these rates. The code was
changed after their first rates (all at 100% already) for faults the independent hyperref papers
showed; the rates did not move.

| | statements and proofs found | word, number, name | extent F1 ≥ 0.9 | proofs: proves right | end marks found / falsely | mentions recall / precision | resolved right or none | **wrong links** |
|---|---|---|---|---|---|---|---|---|
| development (6 papers, 15 pages) | 62 / 62 | 100% | 62 / 62 | 23 / 23 | 16 / 16, 0 / 7 | 82 / 82, 82 / 82 | 82 / 82 (71 targets, 11 none) | **0** |
| held out (3 papers, 7 pages) | 24 / 24 | 100% | 24 / 24 | 10 / 10 | 9 / 9, 0 / 1 | 31 / 31, 31 / 31 | 31 / 31 (27 targets, 4 none) | **0** |

Per statement word, target kind, head style (bold, italic, small caps), class and column layout
(amsart, article one- and two-column) and numbering (section, global): 100% in every cell, dev and
held out alike (`cargo xtask refs-oracle report` lists them). Mentions that rightly resolve to
nothing: dev 11 (another work's, or a block that is not there), held out 4.

Linked papers: of the 9 (dev) and 8 (held out) links to blocks, every one has an inferred mention
under it, and all but one per paper agree on the target; the one is a mention of another work set
with `\ref` (`Theorem 1.1 of [Tanaka]`), which hyperref links and the text reads as external, so the
graph takes the link and says so. The independent hyperref papers (`../../hyperref`, one and two
columns): 16 links each, the text read under 14 (the other two are equation numbers after `is`,
which is not taken for a citing word), no disagreement.

Broken analysers (wrong links, development / held out): trusting the number 11 / 4; every `(n)` a
link 10 / 2; never-ending proofs leave links alone but drop extents to 77.4% / 83.3% (proofs: 5 and
1 no longer detected).

**These numbers say the synthetic set is too easy, not that the problem is solved.** Every paper
comes from one generator with short regular sentences and amsthm's own layouts; the three faults the
independent papers found in an analysis that scored 100% here show how little a perfect score on
this set proves. See below.

## What this does not measure

All of it is LaTeX in one font family (Computer Modern), in two classes, with amsthm's three
styles and two variants of our own, made by one generator whose sentences are short and regular.
Real papers differ: publisher classes and theorem packages (`ntheorem`, `thmtools`, Springer and
Elsevier styles that put the number before the word, heads on a line of their own, framed or
shaded statements, numbers in the margin), statements nested in proofs (`Claim` inside a proof),
`\cref` and its plural forms, ranges written out (`Lemmas 2.1, 2.2 and 2.4–2.6`), references in
footnotes and captions, prose references ("the previous lemma"), Word and other producers, scans,
other fonts and languages. Bibliography citations are out of scope. A score here is an upper bound
for those. Two independent hyperref papers (`../../hyperref`) were read once the analysis existed:
they showed three faults the oracle did not (a big operator drawn into a head's number, a short
statement the layout calls a heading, a link's anchor read as the block before it), each fixed and
tested in `crates/engine/tests/it/reference_graph.rs`.

## Design note: a real-paper set

A pinned, licence-clean set of real papers would be fetched and checked like `cargo xtask corpus`,
never committed, on the plan the layout oracle's README gives:

- **Source and licence.** Only papers whose PDF and source are under a licence on the allowlist that
  allows redistribution (CC-BY-4.0, CC-BY-SA-4.0, CC0-1.0); arXiv says per paper. Papers under
  arXiv's default licence are out. The manifest records each paper's URL, version, licence, SHA-256,
  and why it is in the set (theorem package, publisher style, producer, columns).
- **Fetch.** `cargo xtask refs-corpus fetch` downloads into a git-ignored directory, verifies each
  SHA-256, and fails on any mismatch or any licence outside the allowlist; nothing runs without the
  manifest pinning it.
- **Truth.** Where the source compiles with pdfTeX and free fonts, it is compiled with both bracket
  packages (amsthm and `\ref` are the common case; `ntheorem` and `cleveref` need their own small
  patches), giving the same DVI truth. Otherwise the links of a hyperref build are the truth for
  mentions, and statements are annotated by hand (boxes and words, made by one contributor, checked
  by a second) and scored by boxes. The kinds of truth are reported apart.
- **Held out from the start**, by a fixed rule (a hash of the id), and read only by rates.

Nothing is fetched by this branch.
