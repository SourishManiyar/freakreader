# Math oracle: equation-level truth for LaTeX recovery

This directory is the measuring instrument for recovering LaTeX from typeset equations: equations
whose source we wrote and compiled ourselves, so a recoverer's answer can be scored against what TeX
actually set rather than eyeballed. The first recoverer is the layout reader
(`pdfcraft_render::text::math::layout`); its scores are at the end of this file.

## Files

| File | What it is |
|---|---|
| `equations.toml` | The equation list: id, category, tier (1 plain, 2 structure, 3 expected hard, with the reason), environment, LaTeX body; and the paragraph pages. Written for this repository. 120 equations are for development; 57 more, whose ids start `ho_` and which say `holdout = true`, are held out: written before any recoverer existed, typeset alone only, and to be looked at by their per-category scores, not one by one. |
| `equations.tex`, `equations.pdf` | One equation per page (420 × 200 bp), in the template every candidate is typeset in. |
| `paragraphs.tex`, `paragraphs.pdf` | Running text with inline and numbered display equations, one- and two-column, so a region must be isolated from the words around it. |
| `truth.tsv` | Per occurrence: source, page, view-space box, and the glyphs and rules TeX set for it; per page, every glyph and rule with its owner. Format: `pdfcraft_oracle::tex::TruthSet`. |
| `mutants.tsv` | What TeX sets for each deliberately broken variant (`Mutation`): the typeset comparison must reject every one. |

All but `equations.toml` are generated by `cargo xtask math-oracle generate` and must not be edited.

## How the truth is made

Each equation is bracketed by `\special{pdfcraft:eq:ID:begin}` / `…:end`, and amsmath's equation
numbers by `pdfcraft:tag:…` (a one-line patch of `\maketag@@@`). Each document is run twice:

- to DVI, where `dvitype -output-level=4` lists every glyph (font, size, code) and rule at its exact
  place in scaled points, with the brackets in the order TeX shipped them. Which glyph belongs to
  which equation is therefore TeX's answer, not a guess from where things landed;
- to PDF, the artifact. pdfTeX in PDF mode ignores the specials ("Non-PDF special ignored"); the
  generator checks this by compiling the PDF again with the bracket macros empty and requiring
  byte-identical output. `crates/render/tests/it/math_oracle.rs` checks that the PDF draws exactly
  the glyphs and rules the DVI lists, page by page.

Specials were chosen over `\pdfsavepos`: they give membership as well as position, need no second
pass through the `.aux` file, and come out in shipping order, which is what tells an equation's
glyphs from its number's.

An equation's box is the union of its glyphs' TeX boxes (TFM width, height, depth and italic
correction, read with `kpsewhich`) and its rules, widened by 0.05 bp for pdfTeX's rounding of PDF
positions, in the view space `MathPage` uses (bp from the page's top-left, y down: `view_bp`). The
generator checks every box lies on its page and contains no reference point of any other glyph and
no other rule; the tests check the page's glyphs inside the box are exactly the equation's.

Inline equations in justified text have their operator and relation glue stretched or shrunk by the
line, so they are not a translation of the same equation set alone. Each occurrence therefore keeps
its placed items and a `reference`: the equation typeset alone, which is what candidates are compared
with. The generator checks every occurrence in text is its reference up to that glue (same marks, same
order, same relative baselines). The paragraph document sets `\relpenalty` and `\binoppenalty` to
10000 and `\sloppy` so no inline equation breaks across lines.

Fonts are Computer Modern, AMS Euler and AMS symbols from the TeX Live amsfonts Type 1 set
(OFL-1.1, `../OFL-AMSFonts.txt`). The generator fails if pdfTeX embeds a font from anywhere else.
Never `lmodern`: its licence is not on the allowlist.

## Scoring

Two LaTeX strings are equivalent when TeX sets the same glyphs (font, size, code) and rules (width,
height) at the same places relative to each other, within 0.01 pt: `typeset_equal` in
`pdfcraft_oracle::tex`. `\frac12` and `\frac{1}{2}` are equal; so are `\text{max}` and
`\mathrm{max}` in a subscript, and `\mathrm{tr}(A)` and `\operatorname{tr}(A)`; `\mathrm{log} x`
and `\log x` are not. A candidate is typeset in the truth's environment on a page of its own;
candidates go through one TeX run, and one by one only if that run fails. A candidate TeX cannot set
is a `Verdict::Failed` with the end of the log. `edit_distance` is the cheap TeX-free signal:
Levenshtein over LaTeX tokens.

A recoverer implements `pdfcraft_render::text::math::recover::LatexRecoverer` (a `MathPage` and a
view-space region in, an optional LaTeX body out) and is registered in
`crates/render/examples/math_oracle.rs`.

```sh
cargo xtask math-oracle report                      # every registered recoverer, development and held-out equations apart
cargo xtask math-oracle report --recoverer layout-confident
cargo xtask math-oracle report --recoverer layout --failures   # which development equations fail
cargo xtask math-oracle report --explain sup_squares           # one development equation: answer, confidence, diagnostics
cargo xtask math-oracle report --recoverer identity --no-tex
cargo xtask math-oracle test                        # the tests, including those that run TeX
cargo xtask math-oracle generate --check            # regenerate and require identical bytes
```

The TeX-backed tests are `#[ignore]`d in the plain test run because CI requires every oracle
(`PDFCRAFT_ORACLES_REQUIRED`) and does not install TeX Live; the tests that read committed files,
including that every committed mutant is told apart, run everywhere.

## A real-paper set (not fetched)

Synthetic pages say nothing about papers typeset with other classes, fonts and macro packages. A
pinned, licence-clean set could follow `xtask/src/corpus.rs`: arXiv papers whose listed licence is
CC BY 4.0 or CC0, chosen by hand, fetched as source and PDF from fixed version URLs (`…v2`), verified
by SHA-256 against a committed manifest, kept under the git-ignored `corpus/`, never committed. Only
papers whose sources compile with pdfTeX and fonts on the allowlist would be usable for truth, built
by the same bracket method after inserting the specials into each display environment. Papers under
arXiv's default non-exclusive licence would be excluded, as would any whose PDF embeds a font not on
the allowlist.

## Scores of the layout reader

`pdfcraft_render::text::math::layout` (`cargo xtask math-oracle report`), measured on 2026-11-16 at
commit `6133c4a15` of branch `feat/math-symbols-parser` (working tree clean, no uncommitted change),
with pdfTeX 3.141592653-2.6-1.40.25 (TeX Live 2023/Debian) as the typeset check. Numbers are
typeset-equal / n, the share in parentheses is the **precision**: of the answers given, how many are
right. The three columns are the reader's best answer whether or not it is sure of it
(`layout`), only the answers it calls confident (`layout-confident`: the precision there is the one that
matters for copy-as-LaTeX, since a wrong answer given with confidence is the worst result), and the
confident answers when the caller also tells it whether the equation is inline or displayed
(`layout+env-confident`; the environment is the only thing taken from the truth, as a caller that knows
where the region came from can say; without it a numerator as large as the text is `\frac` in a
display and `\dfrac` in text and the answer is tentative).

Development equations are the 120 the reader was worked on (143 occurrences, 23 of them in running
text, one and two columns). The 57 held-out equations were added before the reader existed, typeset
alone only, and were not used while it was worked on. **They have been read once since**: after the
reader had stopped changing, with the maintainer's agreement, their failures were looked at one by one.
The first run had one confident wrong answer (and a second, with the environment told), both a
fraction followed by glue: a fraction is an ordinary atom to TeX's spacing, and the reader had it as an
inner one. That is fixed (`fractions_are_ordinary_atoms_to_the_glue`) and the held-out set is
development data from here on. The held-out figures below are therefore **not** a measure on unseen
equations any more; the figures before that fix, which were, are in the commit messages and were: held-out
`layout` 50/57 typeset-equal (87.7%, 96.2% of its answers right), confident answers 43/44 right (97.7%),
with the environment told 48/50 (96.0%). Only a new held-out set can measure the reader again.

### What the reader does not read, and says so

Matrices and `array`s, `cases`, `align`/`gather` rows (stacked rows of marks with no rule between
them), braces over and under (`\overbrace`), stacked symbols (`\overset`, `\stackrel`,
`\xrightarrow`, `\substack`), `\binom`, `\middle`, scripts on an empty base, `\cfrac`, and
any glyph of a font or code the symbol table does not know: the answer is `None` (or tentative with
the reason) and the diagnostics name what was met. The categories `matrices`, `cases`, `alignment` and
`decorations` score low for that reason and are not failures of the kind the other categories show: the
reader answers few of them, and what it answers with confidence is right (the one wrong answer among
them, in `matrices`, is a tentative one). `\dfrac` in text and `\tfrac` in a display cannot be told
from `\frac` without the environment.

### Floors

`crates/render/tests/it/math_recover.rs` (`cargo xtask math-oracle test`) holds the reader to floors on
these numbers, with and without the environment: development typeset-equal at least 70%, held-out at
least 85%, the precision of the confident answers at least 98% on both, and per category the floors
listed there. They are where the reader stood when it was last worked on; raise them with it, do not
lower one to make a number pass.
