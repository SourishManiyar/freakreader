# Layout oracle: block-level truth for page layout analysis

This directory measures page layout analysis (`pdfcraft_render::text::page_layout`): synthetic papers
whose LaTeX we wrote and compiled ourselves, so the analysis's columns, blocks, kinds, reading order,
running heads and section tree can be scored against what TeX actually did, not eyeballed. It follows
the math oracle (`../../math/oracle/README.md`) and reuses its machinery (`pdfcraft_oracle::tex`).

## Files

| File | What it is |
|---|---|
| `papers.toml` | The paper list: class, options, geometry, page style, a seed, and the body as directives (`section …`, `par 5 footnote`, `display align`, `figure t wide`, …). Written for this repository. Papers whose id starts `ho_` are held out. |
| `pdfcraftlayout.sty` | The bracket package (`pdfcraft_oracle::tex::layout::package`), as compiled. |
| `<paper>.tex`, `<paper>.pdf` | Each paper, generated from `papers.toml`. The prose is made up by a seeded generator from word lists in `xtask/src/layout_oracle.rs`: no text from papers or books. |
| `truth.tsv` | Per paper its set (dev/holdout), class, columns and size; per page its blocks in shipping order with their kinds, and every glyph and rule with its block. Format: `pdfcraft_oracle::tex::layout::LayoutTruth`. |

All but `papers.toml` are generated by `cargo xtask layout-oracle generate` and must not be edited.

## How the truth is made

Structure is bracketed by `\special{pdfcraft:layout:…}`, listed by `dvitype` in the order TeX shipped
the material, as the math oracle brackets equations:

- paragraphs by LaTeX's paragraph hooks (`para/begin`, `para/end`), each with a kind: `par`, or what
  set it up: `\@startsection` (`heading<level>`, the level being `\@startsection`'s own argument),
  `\@maketitle` (`title`, then `other` for authors and date), the `abstract` environment,
  `\@footnotetext` (`footnote`), and `\pdfcraftenv{item}` in a list;
- the running head and foot and the page number inside them by a patch of `\@outputpage`;
- the footnote rule (`skip`: drawn, scored as nothing);
- floats and captions by `\pdfcraftopen`/`\pdfcraftclose` in the generated source;
- displays by the math oracle's `\pdfcraftbegin`/`\pdfcraftend`, and their numbers by its
  `\maketag@@@` patch. A number joins the equation on its row (amsart sets it on the left, shipped
  before the equation's bracket opens).

A block is a maximal run of items in shipping order with one owner, cut where TeX moved up the page
by more than 30 pt or to the next page: a paragraph broken by a display is two blocks with the display
between them, and a paragraph that runs into the next column is two. Reading order is the order of
the blocks' first items: head, top floats, the columns left to right, footnotes, foot.

Each PDF is compiled a second time with the package reduced to empty macros (no hooks, no patches,
no specials) and must come out **byte-identical**, which shows that neither the specials nor the
patches moved anything (whatsits can change spacing: a bracket after a space blocked `\unskip` in an
early draft, and this check caught it). The generator also requires every glyph to belong to a
block, only AMS Type 1 fonts embedded (Computer Modern, OFL-1.1, `../../math/OFL-AMSFonts.txt`;
the kernel's `\textbullet` would pull in a cm-super TS1 font, so lists use `$\bullet$`), and checks
that no heading swallowed a paragraph (amsart's `\subsection` is run in, which this method does not
bracket: amsart papers use `\section` only). `crates/render/tests/it/layout_oracle.rs` checks that
the PDF draws exactly the glyphs and rules the DVI lists. Generation is byte-reproducible
(`SOURCE_DATE_EPOCH`, `FORCE_SOURCE_DATE=1`, no shell escape): `generate --check` regenerates into a
temporary directory and compares every file.

## Scoring

A found block **matches** a truth block when their sets of glyphs and rules agree with an F1 of at
least **0.9**; a block is right when it matches and its kind is right (heading levels are scored in
the section tree). Per kind: boundary rate, kind rate, and the boundary errors: *merged* (a found
block holds half or more of two truth blocks), *split* (a truth block spread over several found
blocks), *missed* (no found block holds half of it), *spurious* (a found block that stands for no
truth block). Reading order: pages whose matched blocks come in exactly the truth's order with every
block matched, and Kendall's tau over the matched blocks. Running elements (header, footer, page
number): precision and recall. Section tree: headings matched, of those with the right level and the
right parent. Everything is reported for development and held-out papers apart, and by class, column
layout and size.

```sh
cargo xtask layout-oracle report                                 # the analysis, dev and holdout apart
cargo xtask layout-oracle report --analyser all                  # with the deliberately broken analysers
cargo xtask layout-oracle report --failures                      # the development papers' wrong blocks
cargo xtask layout-oracle report --page art11_twocol:3           # what was found on one development page
cargo xtask layout-oracle generate --check                       # regenerate (needs TeX Live), require identical bytes
cargo run -p pdfcraft-engine --example layout_overlay -- IN.pdf 1 out.png   # boxes, order and kinds drawn on a page
```

Three broken analysers prove the harness discriminates (`broken_analysers_score_badly`): one that
never finds columns, one that merges each paragraph into the one before, one that takes running
heads for text. The tests read committed files only; regenerating needs TeX Live.

merging paragraphs 84.3% (paragraph boundaries 62%, 37 merged); taking running heads for text 90.3%
(running recall 0).

## What this does not measure

All of this is LaTeX, in one font family (Computer Modern), from two classes, made by one generator.
Real papers differ: publisher classes (two-column journals with narrow gutters, side captions, marginal
notes), Word and other producers (text drawn word by word, out of order), scans with OCR layers,
other fonts and languages, tables without rules, figures that are images, theorem and proof blocks,
bibliographies, run-in headings, multi-page floats. A score here is an upper bound for those.

## Design note: a real-paper set

A pinned, licence-clean set of real papers would be fetched and checked like `cargo xtask corpus`,
never committed:

- **Source and licence.** Only papers whose PDF is under a licence on the allowlist with the right to
  redistribute (CC-BY-4.0, CC-BY-SA-4.0, CC0-1.0), and whose embedded fonts are themselves allowed
  (or are not shipped: the set is fetched into a git-ignored directory, as `photocraft-corpus` is).
  arXiv's per-paper licences say which; papers under arXiv's default non-exclusive licence are out.
  The manifest records each paper's URL, version, licence, SHA-256 and the reason it is in the set
  (class, publisher style, producer, columns).
- **Fetch.** `cargo xtask layout-corpus fetch` downloads each file, verifies its SHA-256, and fails on
  any mismatch or licence outside the allowlist; nothing runs without the manifest pinning it.
- **Truth.** Where the LaTeX source is available under the same licence, it is compiled with the
  bracket package of this oracle (if it compiles with pdfTeX and the fonts are free), giving the same
  DVI truth; otherwise the truth is a hand-made annotation (block boxes and kinds in a TSV, made by a
  contributor from the rendered page, reviewed by a second), scored with boxes instead of glyph sets.
  The two kinds of truth are reported apart.
- **Held out from the start.** Half the set is held out by a fixed rule (a hash of the id), and
  reported only by rates, as here.

Nothing is fetched by this branch.
